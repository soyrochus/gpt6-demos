# Implementation notes

- React owns observer, UTC clock anchors, playback rate, camera, visibility and selection. A monotonic anchor determines elapsed simulation time. Time jumps and rate changes replace the anchor atomically. Foreground samples and visibility changes read the same clock.
- The pure functions under src/astro are shared by the UI, renderer and Bun tests. They return unit-bearing fields for both geometric and apparent directions. The initial observation makes Orion visible on first launch and explicitly displays the local date and UTC instant.
- The full bright catalogue is validated once per load. Equatorial positions, tangent-plane velocities, colours and magnitudes are uploaded once. One GPU matrix orients the entire star field. Selection projects catalogue directions into the current field of view and applies the horizon and visible-magnitude filters. Camera movement leaves the astronomical state intact.
- The background shader reconstructs each viewing ray, samples the celestial density map and clips the Sun and Moon at the visual horizon. Constellations and the local grid have independent reference frames. On unmount the renderer releases geometries, materials, texture, listeners and its resize observer. Context loss offers recovery.
- Gaia tiles load from the static deployment only when deep fields are enabled, the field of view is 25° or narrower and the view intersects a tile. Cached geometry is reused while moving around. The import is resumable per checksummed tile. A bounded extraction reaching its row limit stops before publishing an incomplete partition.
- The HYG and Gaia importers, binary validation and application code use TypeScript. Astropy is used only to prepare the independent reference fixture. The app and ordinary tests run entirely with Bun and browser code.
